我用 Codex 的 Section 分组与内置 Agent 批量整理 700 个历史话题

因为平时高频使用 Codex，我的左侧栏里积累了差不多 700 个存量话题，一直没有花时间专门归档。时间一长，侧边栏越拉越长，查找具体记录或者管理项目变得非常费劲。

在这次更新之前，我们在 Codex 里管理话题主要依赖三种方式：

  • 置顶（Pinned）： 把经常使用的话题或者正在开发的项目点击 Pin，固定在左侧最上方的 Pinned 区域；
  • 项目文件夹（Project）： 按本地的一个个项目文件夹来组织，可以点击菜单调整不同项目之间或者项目内部话题的排序；
  • 最近对话历史（Recent）： 按照时间顺序罗列最近的对话记录，其中一些话题归属于某个本地项目，也有一些是没有关联项目的零散对话。

但这几种方式都必须严格依托本地磁盘上的真实文件夹。如果只是想按照业务维度把几个不同的项目归纳到一起，在界面上就很难处理。

在产品层面创建 Section 分组

现在 Codex 支持在产品层面直接对任务进行分组，不再强制绑定本地的实际目录。

创建分组的操作很直接：

  1. 点击左侧栏上方的三点菜单；
  2. 在弹出菜单中选择「Section」；
  3. 点击「New Section」，输入分组名称并确认创建。

比如我平时制作自媒体内容，就可以新建一个叫「自媒体」的 Section。创建完成之后，这个 Section 在层级上与 Project 是平级的。

接下来，我们可以把相关的项目直接拖拽到这个分组里。比如我把专门处理小红书内容的 rednote 和自媒体相关的 oil-social-media 拖进「自媒体」分组，整个结构一下子就清楚了。平时维护的各种 Skill 或者经常开发的项目，都可以按照业务类别分别放进不同的 Section。

让 Agent 批量整理与归档任务

如果左侧栏已经积累了大量存量话题，手动逐个去拖拽和分类依然很费时间。

Codex 这次不仅增加了分组功能，还给内置的 Agent 开放了左侧栏相关的操作工具，支持直接让 Agent 帮我们执行批量整理和归档。

面对左侧栏里堆积的约 700 个任务，大部分都是很久以前的对话。我可以新开一个对话窗口，直接对 Agent 下达指令：

「你是不是可以帮我整理一下左侧这些话题了？我现在左侧超过一个月没有对话的，你帮我归档一下。」

这里的归档操作，相当于把长期没有使用的话题收纳起来，不再直接占用左侧栏的可视空间。Agent 接收到指令后，会调用左侧栏提供的新工具，自动筛选出超过一个月未产生对话的任务，并完成批量归档。

除了批量归档，Agent 也能帮我们自动新建 Section 并归类指定项目。比如我可以给它发送这样一段指令：

「你帮我创建一个 Side Project Section，用来放我自己的一些小产品。比如我要把 selector-pro 还有我的 easy demo 等等这些话题，全部放到一个 Side Project Section 里面去。」

发送之后，Agent 会调用 List Projects 和 List Chats 等工具，读取左侧的项目与对话列表，几秒钟之内就完成了创建和移动。左侧栏随即出现了一个新的 Side Projects 分组，对应的几个小产品话题也都准确移动到了里面。

Section 最实用的改变，在于它是纯粹在产品层面建立的逻辑分类。它不需要跟本地的实际磁盘目录强行关联，配合内置 Agent 的批量处理能力，无论是划分业务线还是收纳闲置话题，维护起来都比以前轻便得多。
