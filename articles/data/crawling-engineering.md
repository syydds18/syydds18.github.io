写爬虫 demo 的快感在于十行代码就出数；但让一条数据管道**连续稳定跑过三个月**，靠的全是不性感的部分。

## 一、调度：把「什么时候跑」当成设计题

- **分源错峰**：所有源不挤在同一时刻，避开对方高峰，也分散自己的失败风险；
- **指数退避**：失败重试按 2/4/8 分钟递进，连续三次失败转入告警队列；
- **快照留档**：每次运行留下原始响应的哈希与行数，出问题能回答「昨晚到底抓了什么」。

## 二、数据质量守卫

抓到 ≠ 抓对。每条数据入库前过三道闸：

```python
assert row['title'],   '标题不能为空'
assert row['url'],     '原文链接不能为空'
assert row['date'],    '日期解析失败: ' + raw
```

再加两道软规则：

1. **行数波动告警**：某源今日行数低于过去 7 天中位数的 30% → 疑似改版；
2. **字段漂移检测**：关键字段缺失率超阈值 → 当天数据打上「待人工复核」标记，不静默丢弃。

> 原则：宁可带着标记入库，不可假装一切正常。

## 三、变更感知

页面改版是必然事件。应对方式不是「祈祷别改」，而是**让改版第一时间被发现**：

- 每源保留最近一次成功解析的结构指纹；
- 指纹突变 → 主动告警，附带原始 HTML 片段，五分钟定位。

## 四、日志与回放

所有运行日志按「源 / 日期 / 运行 ID」三维归档，支持按 ID 回放当次的全部输入输出。排查线上问题时，这条能力省下的时间最多。

## 心得总结

| 阶段 | 真正的难点 |
|---|---|
| 跑通 | 无 |
| 跑稳 | 调度、重试、守卫 |
| 跑久 | 变更感知、日志回放 |

爬虫工程的终点不是「抓下来了」，而是**半年后不需要人管**。
